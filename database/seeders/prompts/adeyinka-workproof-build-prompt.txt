## 6. Serper Google Search Integration

Use Serper as the primary live job discovery provider.

Website:

https://serper.dev

Environment variable:

SERPER_API_KEY

Use the documented Serper Google Search endpoint and required request headers.

Keep the API key on the server.

Never expose it in client-side code.

### Job Search Strategy

Search Google-indexed opportunities using combinations of:

- Job title.
- Related keywords.
- Country/location.
- Remote preferences.
- Job platforms.
- Career pages.

Example searches:

"Customer Success" "Nigeria" jobs

site:linkedin.com/jobs/view/ "Operations Coordinator" "Lagos"

site:greenhouse.io "Customer Support" remote

"Business Development Representative" "United Kingdom" hiring

Use a variety of relevant search patterns rather than relying on only one domain.

Each Google query costs one Serper credit. Send at most SERPER_QUERIES_PER_RUN queries per alert run (default 2, maximum 3), one after another rather than in parallel, and store the queries used in each run record.

Serper's free credits are a one-off allowance rather than a monthly one. Keep usage conservative and stop with a clear message when credits run out.

Prefer company career pages and genuine job postings.

Avoid assuming every search result represents an active vacancy.

### Normalised Job Data

Create a standard job record containing:

- ID.
- Title.
- Company, when identifiable.
- Location, when available.
- Source.
- URL.
- Description or available snippet.
- Posting date, when verifiable.
- Remote status, when supported.
- Search timestamp.
- Verification status.

### Critical Data Accuracy Rules

Serper returns Google search results, not guaranteed structured job records.

Therefore:

- Do not invent missing companies.
- Do not fabricate salaries.
- Do not fabricate posting dates.
- Do not assume an indexed job is still open.
- Do not treat Google's snippet date as verified job publication time without sufficient evidence.
- Do not guarantee that a job accepts applicants.
- Do not describe every result as an active opening.

Label uncertain details appropriately.

Where reliable posting dates are unavailable, show **Date not verified**.

### Result Processing

Implement:

- Search query generation.
- API requests with timeouts.
- Error handling.
- Result normalisation.
- URL validation.
- Duplicate removal.
- Basic job-page relevance filtering.
- Search query limits.
- Configurable result limits.
- Quota-aware operation.

When possible, prefer original employer application URLs.

Do not scrape restricted pages or bypass access controls.

Do not depend on LinkedIn pages always being accessible.

Job searches must work even when a particular job-board domain returns no results.
